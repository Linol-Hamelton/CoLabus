# Работа с ядром CoLabus в проекте

Проект-хозяин (host project) — это проект, над которым вы работаете.
Ядро CoLabus — инструмент, а не предмет работы.
Разработка самого ядра ведётся в репозитории разработки, не здесь.

Этот документ — о работе в проекте, где ядро уже установлено (`README.md`, раздел «Как установить в проект»). Версия
ядра: 1.9.6.

## 1. Начало и конец сессии

1. Агент читает `AGENTS.md` (Claude — `CLAUDE.md`, который подключает `AGENTS.md`) и `.ai/TASK.md` проекта.
2. Claude и Codex с включёнными хуками получают сводку состояния и имя своего журнала автоматически. Любой другой
   ассистент открывает сессию сам: `node .ai/bin/protocol-session.cjs start --agent <имя>`; команда печатает
   контекст, идентификатор сессии и имя владельца для журнала, замка и записи проверок.
3. В конце сессии: `git diff`, проверка `node .ai/bin/protocol-validate.cjs --root .` и тесты самого проекта, одна
   запись в своём журнале `.ai/worklog/<имя>.md` с пятью метками (Agent, Action, Result, Next step, Open), затем
   `node .ai/bin/protocol-handoff.cjs record --owner <имя>` — запись проверок с хешем дерева. Следующий агент
   проверяет её командой `node .ai/bin/protocol-handoff.cjs verify`.

## 2. Общие документы и замок

`.ai/TASK.md`, `.ai/PLAN.md`, `.ai/DECISIONS.md`, `.ai/ARCHIVE.md` правит одна сессия за раз:

```powershell
node .ai/bin/protocol-lock.cjs acquire --owner <имя>
node .ai/bin/protocol-lock.cjs release --owner <имя>
node .ai/bin/protocol-lock.cjs status
```

Решение существует только как утверждённый блок в `.ai/DECISIONS.md` с именем человека в строке `Approved by:`.
Предложение агента — это не решение; оно живёт в `.ai/PLAN.md`.

## 3. Слои ядра

Слои лежат в `.ai/core/` и описывают способ работы, а не задачу проекта:

| Слой | Где | О чём |
| --- | --- | --- |
| L0 | `.ai/core/L0-ROOT.md`, `.ai/core/L0-meta/` | корень ядра и мета-процедуры: жизненный цикл процедур, остановка и вопрос владельцу, конфликт источников, изменение решений |
| L1 | `.ai/core/L1-meta/`, `.ai/core/L1-roles/` | ориентация, независимость, роли (реализатор, рецензент, сертификатор, координатор и другие) |
| L2 | `.ai/core/L2-procedures/` | процедуры работы: рамка задачи, выбор модели, контрольные точки, приёмка, эскалация, сценарии |
| L3 | `.ai/core/L3-procedures/`, `.ai/core/L3-tools/` | инструменты и маршруты моделей |
| L4 |  | заметки по клиентам (Claude, Codex, Copilot и другие) |

Схемы записей — `.ai/core/schema/`, сводный каталог — `.ai/core/CATALOG.md` (генерируется, руками не правится).
Идентификаторы решений, на которые ссылаются записи слоёв, расшифрованы в `docs/product/RULES-IN-FORCE.md`.

Полезные команды:

```powershell
node .ai/bin/protocol-core.cjs lint .ai/core            # проверка записей слоёв
node .ai/bin/protocol-core.cjs catalog --check          # каталог совпадает с записями
node .ai/bin/protocol-index.cjs                         # компактный указатель решений и путей в .ai/runtime/
node .ai/bin/protocol-packet.cjs compile-packet --role <роль> --stage <стадия>   # пакет слоёв под роль и стадию задачи
```

## 4. Набор пилота (L4–L6)

Ставится `docs/ops/pilot-install.cjs` на ветку `kernel-pilot-*` (`docs/ops/PILOT-INSTALL.md`). После установки в
проекте появляются:

- обёртка запусков агентов и реестр кандидатов (`docs/ops/PILOT-L4-L6.md`);
- сводка состояния для владельца и журнал его слов (`docs/ops/OWNER-WORDS-JOURNAL.md`, `docs/ops/OWNER-CARD-FORM.md`);
- статистика запусков и проверка записей запусков;
- мастер ключей и проверка каналов (`docs/ops/CHANNELS.md`), рекомендации MCP (`docs/ops/MCP-REQUIRED-AND-OPTIONAL.md`).

Что сделать пользователю после установки набора — `docs/ops/PILOT-NEXT-STEPS.md`. Ветку пилота не отправляйте в
публичный репозиторий: на ней журналы и записи запусков проекта.

## 5. Несколько проектов на одной машине

`docs/ops/fleet/fleet.cjs` ведёт реестр проектов (`--registry <файл>`, схема `fleet/1`; реестр создаёте вы, в продукт
он не входит) и умеет показать состояние (`status`), подтянуть изменения (`pull-all`), поставить ядро в свежий клон
(`setup`) и обновить набор (`update-kit`). Каждая команда, которая что-то меняет, принимает `--plan` и сначала
печатает план. Подробные правила безопасности — в шапке самого файла.

## 6. Обновление ядра

```powershell
git -C <папка продукта> pull
node <папка продукта>/docs/ops/kernel-install.cjs --target <проект> --update
```

Обновление заменяет управляемые файлы (старые — в `.ai/backups/`), обновляет блок ядра в `AGENTS.md` и `CLAUDE.md`
и не трогает состояние проекта (`.ai/TASK.md`, `.ai/PLAN.md`, `.ai/DECISIONS.md`, журналы).
