# Карточка вопроса владельцу

Карточка помогает представить один вопрос, варианты ответа и проверяемые основания.
Это форма для ручного использования. Она сама не выдаёт идентификатор артефакта,
не подтверждает полномочия и не заменяет решение владельца, записанное по правилам
проекта в `AGENTS.md`. Заполненная рекомендация остаётся рекомендацией до ответа.

## Поля

| Поле | Что записать |
|---|---|
| card-id | Идентификатор по правилам проекта; если он ещё не выдан, явно указать это |
| date-utc | Время составления в UTC |
| question | Один конкретный вопрос |
| options | От двух до пяти вариантов; ровно один пометить как рекомендацию |
| default | Действие при отсутствии ответа; `none` означает ожидание |
| binding.kind | `standing`, `candidate` или `plan` |
| anchor | Область действия, полный Git-якорь либо хэш плана согласно таблице ниже |
| checks | Команды, фактические коды завершения, вердикты и пути отчётов |
| revert | План отката до выполнения действия либо `n/a` с причиной |
| provenance | Автор карточки; после ответа — источник ответа и его транскриптор |
| links | Пути первичных файлов относительно репозитория |
| status | `open`, `answered` либо `superseded-by:<id>` |

`checks` заполняются по результатам проверки указанного кандидата. Неизвестный
результат так и обозначается. Токены заключений: `PASS`, `RECOMMENDATION`, `FAIL`,
`BLOCKED`; рекомендация не превращается в положительную сертификацию.

## Привязка вопроса

| Вид | Якорь | Когда требуется новый ответ |
|---|---|---|
| standing | Точная область разрешённых действий | Область или условия меняются либо владелец отменяет разрешение |
| candidate | Имя ветки и полный SHA коммита из Git | Кандидат изменился, получил FAIL либо перестал соответствовать записи о нём |
| plan | SHA-256 файла плана и коммит его публикации | Замороженный план изменился |

Короткий SHA может служить подсказкой читателю, но не точным якорем разрешения
для кандидата. Ответ относится к сформулированному вопросу и его области;
разрешение на проверку не означает разрешение на установку или публикацию.

## Использование

1. Соберите факты, сформулируйте варианты и последствия выбора.
2. До ответа оставьте карточку в состоянии `open` и явно укажите действие по умолчанию.
3. После прямого ответа запишите его источник, время и точную область действия.
   Транскрипция отмечает, кто передал и кто записал ответ; автор не сочиняет ответ владельца.
4. Сохраняйте заполненные записи. Изменение статуса добавляйте новой записью;
   изменённый вопрос оформляйте новой карточкой со ссылкой на предыдущую.

Схема и автоматическая проверка семейства артефактов определяются отдельно
правилами проекта. Эта форма не объявляет их активными.
