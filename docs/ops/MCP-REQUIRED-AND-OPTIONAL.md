# MCP-серверы проекта

MCP помогает находить код и документы. Первичные файлы и воспроизводимые проверки
остаются основанием выводов: ответы сервера не являются Evidence и не входят
в completion gate. Политика внешних инструментов описана в `.ai/docs/PROTOCOL.md`.

## 1. Базовые серверы

### 1.1 Назначение

| Сервер | Для чего | Что сверять в результате |
|---|---|---|
| codebase-memory | Граф кода, зависимости и цепочки вызовов | Корень репозитория, ветку и свежесть индекса |
| qmd | Поиск по Markdown и документам | Коллекцию, путь и исходный текст |

Базовый набор — `codebase-memory` и `qmd`. Для него предусмотрены
локальный запуск, ограничение рабочим деревом, закреплённые версии и отключение
сетевых инструментов там, где сервер их предоставляет. Недоступность сервера
не меняет требования проверок: используйте `rg`, `git ls-files` и чтение файлов,
а ограничение запишите в журнале. Общий индекс может содержать другие проекты;
совпадение из чужого дерева не является ответом о текущем кандидате.

### 1.2 Версии выбирает проект

Перед подключением выберите и проверьте точные версии на своей машине.
Каталог содержит выключенную измеренную запись Semgrep local-v1; наличие
установленных пакетов не предполагается. Остальные записи добавляет проект.

| Сервер | Pin |
|---|---|
| codebase-memory | `codebase-memory-mcp@<VERSION>`: точная версия |
| qmd | scope `@` + `tobilu/qmd`, затем `@<VERSION>`: точная версия |

Установку выполняет пользователь отдельно. Хуки ядра не устанавливают серверы.
Обновление версии требует повторной проверки подключения и размера схем.

### 1.3 Подключение

Замените `<NPM_GLOBAL>` выводом `npm root -g`. Пути пакетов относятся
к установленным на вашей машине версиям.
Фрагменты ниже задают форму конфигурации клиента;
подключение проверяется в выбранном клиенте после настройки.

**Claude Code**, файл `.mcp.json` проекта:

```json
{
  "mcpServers": {
    "codebase-memory": { "type": "stdio", "command": "node", "args": ["<NPM_GLOBAL>/codebase-memory-mcp/bin.js"] },
    "qmd": { "type": "stdio", "command": "node", "args": ["<NPM_GLOBAL>/@tobilu/qmd/bin/qmd", "mcp"] }
  }
}
```

**Codex**, конфигурация клиента:

```toml
[mcp_servers.codebase_memory]
command = "node"
args = ["<NPM_GLOBAL>/codebase-memory-mcp/bin.js"]

[mcp_servers.qmd]
command = "node"
args = ["<NPM_GLOBAL>/@tobilu/qmd/bin/qmd", "mcp"]
```

**Vibe**, конфигурация клиента:

```toml
[[mcp_servers]]
name = "codebase-memory"
transport = "stdio"
command = "node"
args = ["<NPM_GLOBAL>/codebase-memory-mcp/bin.js"]

[[mcp_servers]]
name = "qmd"
transport = "stdio"
command = "node"
args = ["<NPM_GLOBAL>/@tobilu/qmd/bin/qmd", "mcp"]
```

Сама публикация фрагмента не означает проверенный запуск для всех платформ.

### 1.4 Область доступа

Запускайте серверы относительно нужного проекта и выдавайте только права текущей
задачи. Автор проверяет правки обычным `git diff`; ревьюер использует только
читающие инструменты в границах назначения. Для sealed-сертификации MCP отключается:
общие индексы и ответы из других деревьев могут раскрыть чужую работу.

Внешние процессы не становятся песочницей от локального запуска: их установка
и загрузка моделей могут обращаться к сети. Подготовку окружения выполняйте отдельно и явно.
Секреты не записываются в репозиторий; для необязательных серверов указываются
только имена переменных либо способ авторизации.

## 2. Проверка и бюджет схем

Из каталога проекта запустите измеритель с JSON-конфигурацией формы `mcpServers`:

```text
node docs/ops/mcp-schema-budget.cjs --config .mcp.json --server codebase-memory,qmd
node docs/ops/mcp-schema-budget.cjs --config .mcp.json --timeout-ms 60000 --json
```

Он запускает указанные stdio-команды, выполняет `initialize` и `tools/list` со
всеми страницами, считает инструменты и байты схем. Оценка токенов равна
`ceil(bytes / 4)` и не заменяет токенизатор клиента. По умолчанию таймаут сервера
60 секунд; `--timeout-ms` принимает целое число от 100. Лимит — 100 страниц,
повтор курсора или незавершённая пагинация означают неуспешное измерение.

Код 0 означает полный ответ всех выбранных серверов; код 2 — ошибку вызова
либо хотя бы одно неуспешное измерение. Сервер без stdio-команды не опрашивается.
Если ответила только часть серверов, `total` содержит сумму ответивших,
а не бюджет всего проекта. Если никто не ответил, числа равны `null`.
Значения окружения, аргументы команд и сырой stderr сервера не выводятся.
Измеритель сам ничего не устанавливает, но выполняет команды конфигурации:
проверьте их перед запуском.

Сохраняйте результаты своего проекта в `docs/MCP-PROJECT.md`. Первые четыре
столбца должны оставаться в следующем порядке: рекомендатель читает их.

| server | measured tokens | date | command |
|---|---|---|---|
| codebase-memory | не измерено | - | `node docs/ops/mcp-schema-budget.cjs --config .mcp.json --server codebase-memory` |
| qmd | не измерено | - | `node docs/ops/mcp-schema-budget.cjs --config .mcp.json --server qmd` |

Укажите отдельно выбранные и отклонённые дополнения, причины, pin и имя нужной
переменной секрета. Неизмеренные значения не заменяйте нулём. Новое дополнение
или увеличение бюджета требует нового выбора пользователя.

## 3. Дополнительные серверы и скиллы

Начальный каталог `docs/ops/mcp-catalog.json` не содержит дополнительных записей.
Рекомендации появятся после внесения проверенных данных вашего проекта.

```text
node docs/ops/mcp-recommender.cjs <project> --max 3 --json
node docs/ops/mcp-recommender.cjs <project> --catalog <catalog> --max 5
```

Рекомендатель читает признаки проекта, существующие подключения, скиллы и
записанные измерения. Он ничего не устанавливает и не запускает; код 0 означает
составленный результат, код 2 — ошибку входов. `--max` допускает целые 3–5;
если подходящих записей меньше, список не дополняется случайными рекомендациями.

Предлагаются только записи с `provenance: host-config`, подходящим точным pin
и проверяемой командой установки. Неточная версия, непроверенная запись или
команда с заглушками попадают в `NOT VERIFIED, NOT OFFERED`. Версионный pin
содержит имя пакета и точную версию; для ревизии используется полный commit id.
Размещённый или встроенный сервис без такого pin не получает готовую команду.
Нужный секрет обозначается именем переменной или требованием OAuth.

Пользователь выбирает дополнения; выбор записывается в `docs/MCP-PROJECT.md`.
Установка — отдельное действие, за которым следует измерение. Не переносите
состояние чужой машины или готовые числовые бюджеты в свою таблицу.

## 4. Доставка инструментов

`<product>/docs/ops/pilot-install.cjs` копирует инструменты и данные по
`<product>/docs/ops/pilot-kit.json`. Копирование документа не настраивает MCP-клиент,
не устанавливает сервер и не создаёт заполненный документ выбора проекта.
Пути установленного набора и следующие шаги перечислены в
`docs/ops/PILOT-NEXT-STEPS.md`. Конфигурация, доступы и проверка подключения
остаются действиями пользователя.

## Advisory-диагностика установки

Channels doctor читает проектный `.mcp.json` без запуска серверов. Настройка stdio
не доказывает изоляцию ОС или запрет сетевого доступа:
эти runtime-свойства остаются непроверенными. Списки клиента подтверждают только
наблюдаемую доступность. Отсутствие или повреждение данных не меняет gates установки.
Встроенные pin соответствуют проверенному набору поставки; иная версия остаётся
непроверенной, а не объявляется неисправной.

Необязательный проектный `docs/ops/mcp-minimum-evidence.json` хранит снимок `tools/list`.
Точная форма JSON: `schema` = `mcp-minimum-evidence/1`, `configSha256` = SHA-256
точных байтов `.mcp.json`, `budgetTokens` = положительное целое число, `servers` =
объект, где каждому серверу соответствует непустой массив инструментов. Поля
инструмента: `name`, необязательное `description`, `inputSchema` с `type: object`.
Имена уникальны. Нужны данные всех выбранных серверов, включая дополнительные.
Диагностика складывает `ceil(число байтов UTF-8 JSON / 4)` по серверам: это оценка
токенов измеренного снимка, не точный tokenizer и не проверка актуальности runtime.
Изменение конфига, неполный снимок, неверное число, дубли JSON или нечитаемый путь
дают `unverified`. Снимок создаётся после явно выполненного локального измерения;
doctor не запускает серверы и не создаёт этот файл автоматически.

## Semgrep local-v1: необязательный выбор проекта (2.0.2)

PROTO-DEC-0254 разрешает Semgrep только author/fixer. Минимум qmd + codebase-memory
не меняется; отсутствие, неверная версия и сбой optional не меняют обязательный
doctor OK, допуск места или gates. Каталог хранит provenance `local-cli`, поэтому
recommender по прежнему не предлагает эту запись: выбор делает владелец проекта.

Сначала задайте `COLABUS_SEMGREP_BIN` абсолютным путём локального executable;
если override отсутствует, resolver ищет `semgrep.exe` (Windows) или `semgrep`
в PATH. Неверный override не заменяется другим executable. Установка вручную:
`python -m venv PATH_TO_VENV`, затем Python этого venv: `-m pip install semgrep==1.183.0`.
Ядро не устанавливает Python, пакеты, приложение GitHub и не вызывает login.

Создайте `.ai/mcp-optional.json` выбранного проекта с явным выбором:

```json
{"schema":"optional-mcp/1","semgrep":{"enabled":true,"version":"1.183.0","profile":"local-v1","schemaBytes":3251,"schemaTokensEstimate":813}}
```

Installer, включая `-Force`, не создаёт и не перезаписывает локальный выбор.
Допускается только `version=1.183.0`, `profile=local-v1`,
`schemaBytes=3251`, `schemaTokensEstimate=813`. Иное значение получает именованный
warning и Semgrep пропускается. Без файла optional выключен.

Проверка: `node .ai/bin/mcp-wiring.cjs doctor --root PROJECT --probe-semgrep`.
Без `--probe-semgrep` doctor ничего не запускает для optional и пишет
`unverified-version`. Probe проверяет реальный CLI pin при старте endpoint,
initialize, все страницы tools/list, три имени и актуальный бюджет схемы.
Штатный serverInfo Semgrep 1.29.0 не является версией CLI 1.183.0.

`node .ai/bin/mcp-wiring.cjs semgrep apply --root PROJECT` измеряет профиль и
показывает dry run; `--apply` создаёт `.ai/semgrep-mcp.json` внутри проекта.
Более 3251 UTF-8 bytes или 813 оценочных токенов отвергаются. Чужой существующий
файл, link/hardlink и цель за границей проекта не заменяются; одинаковый повтор
ничего не пишет. Общий `apply --home` обслуживает прежний минимум, без optional.
Сохранённый JSON пригоден для ручного измерения; launcher каждый раз строит
актуальный дескриптор по выбору проекта, а не доверяет сохранённому артефакту.

| Клиент | Доставка в author/fixer | Certifier/sealed/unknown |
|---|---|---|
| Claude | strict per-seat JSON command/args/env | strict без Semgrep, даже при opt-out |
| Codex | ignore-user-config и overrides, включая env | user config игнорируется |
| Vibe 2.26.1 | VIBE_MCP_SERVERS, три точных enabled-tools | запись semgrep disabled |
| Kilo | KILO_CONFIG_CONTENT, command-array и environment | запись semgrep enabled=false |
| MiMo | измеренный MIMOCODE_CONFIG_CONTENT, local формат | запись semgrep enabled=false |
| Kimi | mcp.json в приватном home запуска внутри проекта | приватный home без optional |
| Copilot, Qwen | not-wired-for-semgrep, unmeasured; флаги не выдуманы | optional не добавляется; Qwen сохраняет bare |

Cline использует собственные настройки; ядро их не читает/не меняет.
OpenCode сохраняет прежнее ограничение допуска. Таблица описывает механизм;
живые сеансы моделей и сетевой трафик каждого клиента отдельно не аттестованы.

Endpoint `.ai/bin/lib/semgrep-seat-server.cjs` запускает CLI по абсолютному пути,
shell=false, cwd проекта, timeout и ограничение буфера. Разрешены только
get_supported_languages, semgrep_scan_with_custom_rule, get_abstract_syntax_tree.
Разрешённый custom-rule scan принимает код и локальный YAML; это отдельный
метод от запрещённого write_custom_semgrep_rule. Env отключает metrics,
MCP tracing, version check и остальные scan/cloud tools, включает три local tool.
Env-флаги сами не убирают prompts/resources: фильтр отдельно отклоняет
setup_semgrep_mcp, write_custom_semgrep_rule, prompts/get, resources/read и
прочие методы. Roots/list обслуживается локально URI выбранного проекта;
elicitation и login клиенту не передаются. До проверки схемы tools/call запрещён;
превышение бюджета повторного tools/list вновь запрещает вызовы.
Ограничительная строка включается в пакет author/fixer.

Известный дефект доставки (измерение smi2, 2026-11-02): сервер CLI 1.183.0
завершает custom-rule scan за секунды (прямой CLI 0.6-2.1 s; сам scan внутри
сервера до ~4 s, в stderr сервера `semgrep_scan_with_custom_rule succeeded`),
но отдаёт JSON-RPC ответ tools/call только после чтения следующего входного
сообщения или при завершении процесса. Воспроизведено ограниченным probe:
ping через ~1.8 s после отправки tools/call снимает зависание — ответ приходит
через ~70 ms; без нового входного сообщения ответ не доставляется 30-60 s.
Дефект не зависит от env места (полное родительское окружение и включённый
tracing также зависают) и не находится в wiring ядра: roots/list обслужен
локально, загрузка правил и сеть не участвуют. Endpoint fail-soft: зависший
tools/call завершается именованным warning SEMGREP_RESPONSE_STALL, остальные
методы — прежним SEMGREP_TIMEOUT; optional остаётся optional, обязательные
серверы места продолжают работать. Команда doctor с `--probe-semgrep`
проверяет запуск и каталог; проверка tools/call требует отдельного локального
MCP-клиента и правила. Успешный probe не подтверждает доставку результата scan.

Записи optional-механизма ядра ограничены worktree. Сам Semgrep использует
временный каталог ОС для кода и rule.yaml и удаляет его в finally.
Proxy не является OS sandbox. API-токены/OAuth из окружения родителя
не передаются; доступ процесса к файлам пользовательского home отдельно
не изолирован. Отсутствие сетевых обращений не доказывается cwd или metrics-off.

Измерение 2026-11-02: 3 tools, 3251 bytes компактного tools JSON,
ceil(bytes/4)=813; provenance local-cli; sha256
8b336607dbf06b8e3b1688f5290ce72000fe307f703f8e20ab632031ec938d04.
Это оценка, не точный токенизатор модели. Независимая сертификация,
живые Copilot/Qwen и сетевая аттестация остаются оператору.
