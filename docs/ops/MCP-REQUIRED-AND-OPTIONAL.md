# MCP-серверы проекта

MCP помогает находить код и документы. Первичные файлы и воспроизводимые проверки
остаются основанием выводов: ответы сервера не являются Evidence и не входят
в completion gate. Политика внешних инструментов описана в `.ai/docs/PROTOCOL.md`.

## 1. Базовые серверы

### 1.1 Назначение

| Сервер | Для чего | Что сверять в результате |
|---|---|---|
| serena | Символы, определения и ссылки в коде | Рабочее дерево и содержимое найденного файла |
| codebase-memory | Граф кода, зависимости и цепочки вызовов | Корень репозитория, ветку и свежесть индекса |
| qmd | Поиск по Markdown и документам | Коллекцию, путь и исходный текст |

Базовый набор — `serena`, `codebase-memory`, `qmd`. Для него предусмотрены
локальный запуск, ограничение рабочим деревом, закреплённые версии и отключение
сетевых инструментов там, где сервер их предоставляет. Недоступность сервера
не меняет требования проверок: используйте `rg`, `git ls-files` и чтение файлов,
а ограничение запишите в журнале. Общий индекс может содержать другие проекты;
совпадение из чужого дерева не является ответом о текущем кандидате.

### 1.2 Версии выбирает проект

Перед подключением выберите и проверьте точные версии на своей машине.
Каталог поставляется пустым; наличие установленных пакетов не предполагается.

| Сервер | Pin |
|---|---|
| serena | `<SERENA_COMMIT>`: полный 40-символьный commit id |
| codebase-memory | `codebase-memory-mcp@<VERSION>`: точная версия |
| qmd | scope `@` + `tobilu/qmd`, затем `@<VERSION>`: точная версия |

Установку выполняет пользователь отдельно. Хуки ядра не устанавливают серверы.
Обновление версии требует повторной проверки подключения и размера схем.

### 1.3 Подключение

Замените `<NPM_GLOBAL>` выводом `npm root -g`, `<SERENA_COMMIT>` — pin из
таблицы выше. Пути пакетов относятся к установленным на вашей машине версиям.
Фрагменты ниже задают форму конфигурации клиента;
подключение проверяется в выбранном клиенте после настройки.

**Claude Code**, файл `.mcp.json` проекта:

```json
{
  "mcpServers": {
    "serena": {
      "type": "stdio",
      "command": "uvx",
      "args": ["--from", "git+https://github.com/oraios/serena@<SERENA_COMMIT>", "serena", "start-mcp-server",
               "--context", "claude-code", "--project-from-cwd",
               "--open-web-dashboard", "False", "--enable-web-dashboard", "False", "--enable-gui-log-window", "False"]
    },
    "codebase-memory": { "type": "stdio", "command": "node", "args": ["<NPM_GLOBAL>/codebase-memory-mcp/bin.js"] },
    "qmd": { "type": "stdio", "command": "node", "args": ["<NPM_GLOBAL>/@tobilu/qmd/bin/qmd", "mcp"] }
  }
}
```

**Codex**, конфигурация клиента:

```toml
[mcp_servers.serena]
command = "uvx"
args = ["--from", "git+https://github.com/oraios/serena@<SERENA_COMMIT>", "serena", "start-mcp-server",
        "--project-from-cwd", "--context=codex",
        "--enable-web-dashboard", "False", "--open-web-dashboard", "False", "--enable-gui-log-window", "False"]

[mcp_servers.codebase_memory]
command = "node"
args = ["<NPM_GLOBAL>/codebase-memory-mcp/bin.js"]

[mcp_servers.qmd]
command = "node"
args = ["<NPM_GLOBAL>/@tobilu/qmd/bin/qmd", "mcp"]
```

**Vibe**, конфигурация клиента:

```toml
[[mcp_servers]]
name = "serena"
transport = "stdio"
command = "uvx"
args = ["--from", "git+https://github.com/oraios/serena@<SERENA_COMMIT>", "serena", "start-mcp-server",
        "--context", "agent", "--project-from-cwd",
        "--enable-web-dashboard", "False", "--open-web-dashboard", "False", "--enable-gui-log-window", "False"]

[[mcp_servers]]
name = "codebase-memory"
transport = "stdio"
command = "node"
args = ["<NPM_GLOBAL>/codebase-memory-mcp/bin.js"]

[[mcp_servers]]
name = "qmd"
transport = "stdio"
command = "node"
args = ["<NPM_GLOBAL>/@tobilu/qmd/bin/qmd", "mcp"]
```

Контекст `agent` в последнем фрагменте требует проверки в вашем клиенте.
Сама публикация фрагмента не означает проверенный запуск для всех платформ.

### 1.4 Область доступа

Запускайте серверы относительно нужного проекта и выдавайте только права текущей
задачи. Автор проверяет правки обычным `git diff`; ревьюер использует только
читающие инструменты в границах назначения. Для sealed-сертификации MCP отключается:
общие индексы и ответы из других деревьев могут раскрыть чужую работу.

В приведённых фрагментах панели Serena отключены. Внешние процессы не становятся
песочницей от этих флагов: их установка, загрузка моделей или языковых серверов
могут обращаться к сети. Подготовку окружения выполняйте отдельно и явно.
Секреты не записываются в репозиторий; для необязательных серверов указываются
только имена переменных либо способ авторизации.

## 2. Проверка и бюджет схем

Из каталога проекта запустите измеритель с JSON-конфигурацией формы `mcpServers`:

```text
node docs/ops/mcp-schema-budget.cjs --config .mcp.json --server serena,codebase-memory,qmd
node docs/ops/mcp-schema-budget.cjs --config .mcp.json --timeout-ms 60000 --json
```

Он запускает указанные stdio-команды, выполняет `initialize` и `tools/list` со
всеми страницами, считает инструменты и байты схем. Оценка токенов равна
`ceil(bytes / 4)` и не заменяет токенизатор клиента. По умолчанию таймаут сервера
60 секунд; `--timeout-ms` принимает целое число от 100. Лимит — 100 страниц,
повтор курсора или незавершённая пагинация означают неуспешное измерение.

Код 0 означает полный ответ всех выбранных серверов; код 2 — ошибку вызова
либо хотя бы одно неуспешное измерение. Сервер без stdio-команды не опрашивается.
Если ответила только часть серверов, `total` содержит сумму ответивших,
а не бюджет всего проекта. Если никто не ответил, числа равны `null`.
Значения окружения, аргументы команд и сырой stderr сервера не выводятся.
Измеритель сам ничего не устанавливает, но выполняет команды конфигурации:
проверьте их перед запуском.

Сохраняйте результаты своего проекта в `docs/MCP-PROJECT.md`. Первые четыре
столбца должны оставаться в следующем порядке: рекомендатель читает их.

| server | measured tokens | date | command |
|---|---|---|---|
| serena | не измерено | - | `node docs/ops/mcp-schema-budget.cjs --config .mcp.json --server serena` |
| codebase-memory | не измерено | - | `node docs/ops/mcp-schema-budget.cjs --config .mcp.json --server codebase-memory` |
| qmd | не измерено | - | `node docs/ops/mcp-schema-budget.cjs --config .mcp.json --server qmd` |

Укажите отдельно выбранные и отклонённые дополнения, причины, pin и имя нужной
переменной секрета. Неизмеренные значения не заменяйте нулём. Новое дополнение
или увеличение бюджета требует нового выбора пользователя.

## 3. Дополнительные серверы и скиллы

Начальный каталог `docs/ops/mcp-catalog.json` не содержит дополнительных записей.
Рекомендации появятся после внесения проверенных данных вашего проекта.

```text
node docs/ops/mcp-recommender.cjs <project> --max 3 --json
node docs/ops/mcp-recommender.cjs <project> --catalog <catalog> --max 5
```

Рекомендатель читает признаки проекта, существующие подключения, скиллы и
записанные измерения. Он ничего не устанавливает и не запускает; код 0 означает
составленный результат, код 2 — ошибку входов. `--max` допускает целые 3–5;
если подходящих записей меньше, список не дополняется случайными рекомендациями.

Предлагаются только записи с `provenance: host-config`, подходящим точным pin
и проверяемой командой установки. Неточная версия, непроверенная запись или
команда с заглушками попадают в `NOT VERIFIED, NOT OFFERED`. Версионный pin
содержит имя пакета и точную версию; для ревизии используется полный commit id.
Размещённый или встроенный сервис без такого pin не получает готовую команду.
Нужный секрет обозначается именем переменной или требованием OAuth.

Пользователь выбирает дополнения; выбор записывается в `docs/MCP-PROJECT.md`.
Установка — отдельное действие, за которым следует измерение. Не переносите
состояние чужой машины или готовые числовые бюджеты в свою таблицу.

## 4. Доставка инструментов

`docs/ops/pilot-install.cjs` копирует инструменты и данные по
`docs/ops/pilot-kit.json`. Копирование документа не настраивает MCP-клиент,
не устанавливает сервер и не создаёт заполненный документ выбора проекта.
Пути установленного набора и следующие шаги перечислены в
`docs/ops/PILOT-NEXT-STEPS.md`. Конфигурация, доступы и проверка подключения
остаются действиями пользователя.

## Advisory-диагностика установки

Channels doctor читает проектный `.mcp.json` без запуска серверов. Настройка stdio
и отключённые dashboard не доказывают изоляцию ОС или запрет сетевого доступа:
эти runtime-свойства остаются непроверенными. Списки клиента подтверждают только
наблюдаемую доступность. Отсутствие или повреждение данных не меняет gates установки.
Встроенные pin соответствуют проверенному набору поставки; иная версия остаётся
непроверенной, а не объявляется неисправной.

Необязательный проектный `docs/ops/mcp-minimum-evidence.json` хранит снимок `tools/list`.
Точная форма JSON: `schema` = `mcp-minimum-evidence/1`, `configSha256` = SHA-256
точных байтов `.mcp.json`, `budgetTokens` = положительное целое число, `servers` =
объект, где каждому серверу соответствует непустой массив инструментов. Поля
инструмента: `name`, необязательное `description`, `inputSchema` с `type: object`.
Имена уникальны. Нужны данные всех выбранных серверов, включая дополнительные.
Диагностика складывает `ceil(число байтов UTF-8 JSON / 4)` по серверам: это оценка
токенов измеренного снимка, не точный tokenizer и не проверка актуальности runtime.
Изменение конфига, неполный снимок, неверное число, дубли JSON или нечитаемый путь
дают `unverified`. Снимок создаётся после явно выполненного локального измерения;
doctor не запускает серверы и не создаёт этот файл автоматически.
